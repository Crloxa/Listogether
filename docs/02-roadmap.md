# 阶段总览

阶段按可验证的闭环推进。每个阶段完成前，必须通过该阶段出口条件，并在 `docs/TEST_EVIDENCE.md` 留下证据。

| 阶段 | 目标 | 出口条件 |
| --- | --- | --- |
| Phase 0 | 项目骨架、协议和开发自检 | 文档、启动命令、协议校验和测试基线成立 |
| Phase 1 | 房间、成员、控制面和邀请 | 两个浏览器可通过互联网链接加入并看到一致房间状态 |
| Phase 2 | WebRTC 音频和同步屏障 | 房主本地音频可被成员听到，切歌/拖动/重连可同步 |
| Phase 3 | 队列、点歌、本地文件和迟到处理 | 多人协作播放闭环完成，单个慢成员不阻塞房间 |
| Phase 4 | 官方平台识别、OAuth 和安全加固 | 可播放性状态清晰，鉴权安全，MVP 风险和失败路径可复核 |

阶段之间不要求一次性实现所有增强体验。聊天、反应、歌词、收藏、导入导出、Media Session 和 PWA 在核心闭环稳定后接入，不能牺牲房间同步和安全性。

## MVP 总验收

- [ ] 房主可本地启动服务并创建房间链接。
- [ ] 互联网中的两个浏览器可安全加入同一房间。
- [ ] 房主本地音频可通过 WebRTC 被成员听到。
- [ ] 播放、暂停、拖动状态可同步；只有播放下一首使用准备屏障和统一开始时间。
- [ ] 成员可单独重新同步；迟到成员只收到提示，不自动改变当前歌曲进度。
- [ ] 全房间播放下一首时，在线成员统一对齐时间戳并同时开始。
- [ ] 点歌、审核、排序、投票跳过、去重和权限有效。
- [ ] 断线重连恢复，房主离开有明确转移或结束行为。
- [ ] 外部链接、OAuth、VIP/地区/失效来源显示明确状态，不暴露凭据。
- [ ] 构建、测试、启动冒烟和双浏览器场景均有证据链。
